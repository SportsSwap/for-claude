# Sawnx Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local, FYI-style web front end (Sawnx) for `tra`: clients and job status, folders and file notes, import (read or store only), figures confirmed on screen, prepare, review notes, and an AI reader that is built but off.

**Architecture:** A Flask app inside the `tra` package, served by werkzeug on 127.0.0.1 only, started by `tra web` or `Sawnx.cmd`. Routes are thin; behaviour lives in small service modules that call the existing tool code (`ingest_file`, `file_document`, `read_figures`/`write_figures`, `prepare_client`, `DocumentIndex`, `AuditLog`). No database: the existing files plus `review.json`, `last_prepare.json`, `client_notes.json` and `sawnx.json`.

**Tech Stack:** Python 3.12, Flask 3 (Jinja2 templates, werkzeug server), plain CSS and JS (no CDN, no build step), pytest with Flask's test client.

**Spec:** `docs/specs/2026-10-18-sawnx-design.md` (and the binding `docs/specs/2026-10-14-tax-return-assistant-design.md`).

## Global Constraints

- Bind to `127.0.0.1` only. Default port `8766`; fall back to a free port if taken.
- Every request needs the session cookie `sawnx_session` (value = a `secrets.token_urlsafe(32)` key made per start); `Host` must be `127.0.0.1:<port>` or `localhost:<port>`; every POST needs `Origin` = `http://127.0.0.1:<port>` or `http://localhost:<port>`. Otherwise 403.
- Responses carry `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, and `Content-Security-Policy: default-src 'self'; frame-ancestors 'self'` (no external fonts, scripts or styles: success criterion 4 allows no network call but FYI and Xero).
- Every write goes through the output guard (`atomic_write_text` / `check_value` / `check_rows`). Original upload filenames are never written anywhere.
- No new tax logic. CLI behaviour is unchanged except `tra new` sharing code with Sawnx and the new `tra web` command.
- Copy: plain English for an accountant; money via `tra.money.format_dollars`; "Draft only … Nothing has been lodged." wherever a result is shown.
- Fonts: system stacks (`"Segoe UI", system-ui, sans-serif`; `"Cascadia Mono", Consolas, ui-monospace, monospace`) instead of the mockup's Google-hosted IBM Plex, because of the no-network rule. Colours from the approved mockup: ground `#0A0A0B`, side `#0E0E10`, surface `#141416`, line `#232327`, text `#ECECEE`, muted `#A1A1A8`, accent `#7DD3C0`, High `#FF9A9A` on `#3A1717`, Medium `#F5CB7A` on `#3A2C10`, Low `#C4C4CA` on `#232327`.
- Tests generate all data at runtime; nothing committed may fail `tests/test_repo_hygiene.py`. Write the failing test first.
- Commits only when the user says so; never push.
- Run tests with `.venv\Scripts\python -m pytest`; lint with `.venv\Scripts\python -m pyflakes src tests`.

## Review Focus

1. `figures.csv` open in Excel while a tick is clicked: nothing is half-written and the page says to close Excel (Task 6).
2. The same file uploaded twice (double-click, two tabs): the second is reported as a duplicate, not filed again (Task 4).
3. An upload whose original name holds a person's name or a TFN: the name appears nowhere under `TRA_HOME` afterwards (Task 4).
4. A file that's too big (over 50 MB) or of a type not on the list: refused with a plain message before anything is saved (Task 4).
5. A client code typed in lower case, with spaces or with path characters (`../X`), in the form or in a URL: refused or 404, never a file outside `TRA_HOME` (Tasks 2 and 3).
